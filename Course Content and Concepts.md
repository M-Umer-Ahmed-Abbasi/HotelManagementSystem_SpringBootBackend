# Essential Spring Boot Concepts for Complete Project Development

Based on the provided slides, the following concepts are required to build a complete, production-ready Spring Boot application, structured by development layer.

---

## 1. Core Application Architecture (Layered Design)

A complete Spring Boot project follows a layered architecture, typically structured as **Controller** $\rightarrow$ **Service** $\rightarrow$ **Repository** $\rightarrow$ **Database**, for separation of concerns.

| Component | Key Annotation | Purpose |
| :--- | :--- | :--- |
| **Controller Layer** | `@RestController` | Handles incoming web requests and sends back responses. Uses annotations like `@RequestMapping`, `@GetMapping`, `@PostMapping`, etc., to map endpoints. |
| **Service Layer** | `@Service` | Encapsulates the core **business logic** (workflows, business rules) and defines **transaction boundaries** using `@Transactional`. |
| **Repository Layer** | `@Repository` | An abstraction layer for **data access and persistence** logic, typically extending Spring Data JPA interfaces. |
| **Data Transfer Objects (DTOs)** | N/A | Used to transfer data between layers and format responses to clients, avoiding exposure of internal JPA entities. |

---

## 2. REST API Development

The application's interface is built as a **REST API** (Representational State Transfer).

| Concept | Description |
| :--- | :--- |
| **HTTP Methods (CRUD)** | Mapped to resource operations: **`GET`** (Read), **`POST`** (Create), **`PUT`** (Full Update), **`PATCH`** (Partial Update), and **`DELETE`** (Remove). |
| **Statelessness** | Each HTTP request is independent; the server must not store client session state between requests. |
| **Filters & Interceptors** | **Filters** (Servlet API) run *before* the Spring `DispatcherServlet` (e.g., for JWT token extraction). **Interceptors** (Spring MVC) run *after* the `DispatcherServlet` (e.g., for specific business/role checks). |
| **HTTP Status Codes** | Standardized response codes: **`200 OK`**, **`201 Created`**, **`400 Bad Request`**, **`404 Not Found`**, **`500 Internal Server Error`**. |
| **External API Integration** | Clients used to consume other services: **`FeignClient`** (declarative/microservices) or **`WebClient`** (reactive/non-blocking I/O). |

---

## 3. Data Persistence (JPA & Spring Data)

This covers object-relational mapping (ORM) using **JPA** (implemented by **Hibernate**) and the **Spring Data JPA** abstraction.

### Entity Mapping (JPA/Hibernate)

| Annotation | Purpose |
| :--- | :--- |
| `@Entity` | Marks a Java class as a persistent entity to be mapped to a database table. |
| `@Table` | Specifies the database table name and can define unique constraints. |
| `@Id` & `@GeneratedValue` | Defines the primary key and its automatic generation strategy (e.g., `IDENTITY`, `SEQUENCE`). |
| **Relationships** | `@OneToMany`, `@ManyToOne`, `@OneToOne`, `@ManyToMany` define how entities relate. |
| `@JoinColumn` | Specifies the foreign key column used for a relationship. |

### Spring Data Repository

* **Repository Interfaces:** Spring Data provides interfaces to minimize boilerplate code:
    * `CrudRepository`: Provides essential **CRUD** operations (`save`, `findById`, `findAll`, `deleteById`).
    * `JpaRepository`: Extends `CrudRepository`, adding features like batch operations, **pagination**, and **sorting**.
* **Derived Query Methods:** Queries are automatically generated by Spring Data based on method names (e.g., `findByEmail(String email)`).
* **Persistence Context:** A first-level cache managed by the `EntityManager` that tracks entity state (including "dirty checking") before synchronizing changes with the database.

---

## 4. Transactional Management

Ensures data integrity by treating a series of database operations as a single unit of work.

* **ACID Properties:** Transactions adhere to **Atomicity**, **Consistency**, **Isolation**, and **Durability**.
* `@Transactional`: The key annotation for declarative transaction management, automatically handling the **begin**, **commit**, or **rollback** of a transaction based on success or exceptions.
* **Isolation Levels:** Control how concurrent transactions interact (e.g., `READ_COMMITTED` prevents other transactions from reading uncommitted changes).
* **Propagation Behavior:** Determines if a method should use an existing transaction or create a new one (e.g., `REQUIRED`, `REQUIRES_NEW`).

---

## 5. Security (Spring Security)

The framework for handling authentication and authorization in a Spring Boot application.

| Concept | Description |
| :--- | :--- |
| **Authentication** | **Who are you?** The process of verifying a user's identity, managed by `AuthenticationManager` and `UserDetailsService`. |
| **Authorization** | **What can you do?** The process of checking permissions *after* authentication, based on roles and authorities. |
| **RBAC** | **Role-Based Access Control**—managing access using **Roles** (e.g., `ADMIN`) and **Authorities** (specific permissions like `READ_USER`). |
| **Access Control** | Enforced via the `SecurityFilterChain` (URL-level checks like `.hasRole("ADMIN")`) or using method-level annotations like `@PreAuthorize`. |
| **JWT** | **JSON Web Token** is a common protocol for stateless authentication, implemented via a custom **Filter** in the security filter chain. |

---

## 6. Robustness and Quality

Concepts essential for building a reliable, maintainable, and well-documented API.

| Concept | Purpose |
| :--- | :--- |
| **Global Exception Handling** | Uses **`@RestControllerAdvice`** to centralize error handling, translating internal exceptions into clean, consistent **HTTP Status Codes** for the client. |
| **Custom Runtime Exceptions** | Creating domain-specific exceptions (e.g., `ProductNotFoundException`) that extend `RuntimeException` for easy handling without required `try-catch` blocks. |
| **API Documentation** | Using **Swagger/OpenAPI** annotations (`@OpenAPIDefinition`, `@Tag`, `@Operation`) to automatically generate interactive API documentation. |
| **Resilience Patterns** | Implementing patterns like **Circuit Breaker** (e.g., with Resilience4J), **Retry**, and **Timeout** for graceful handling of external API failures. |
